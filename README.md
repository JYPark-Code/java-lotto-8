# 로또 발매기 (Lotto)
## 1. 기능 요구사항
###   1-1. 로또 구매

* 사용자는 로또 구입 금액을 입력한다.

* 구입 금액은 1,000원 단위여야 한다. 로또 한 장의 가격은 1,000원이다.

* 1,000원으로 나누어 떨어지지 않으면 예외를 발생시키고 에러 메시지를 출력한 뒤 해당 입력부터 다시 받는다.

* 구입 금액에 따라 발행할 로또 개수를 계산한다. (예: 8,000원 → 8장)



### 1-2. 로또 발행

* 한 장의 로또는 1부터 45까지의 숫자 중 중복되지 않는 6개의 숫자로 구성된다.

* Randoms.pickUniqueNumbersInRange(1, 45, 6)을 사용해 번호를 생성한다. (camp.nextstep.edu.missionutils.Randoms)

* 생성된 번호는 오름차순으로 정렬된 상태로 출력한다.

* 구입한 개수만큼 로또를 발행하고, 발행된 모든 로또 번호를 출력한다.

출력 예시
``` JAVA
8개를 구매했습니다.
[8, 21, 23, 41, 42, 43]
[3, 5, 11, 16, 32, 38]
...
```

### 1-3. 당첨 번호 입력

* 당첨 번호(6개)를 입력받는다.

  * 형식: 1,2,3,4,5,6

  * 쉼표(,) 기준으로 split 후 정수 리스트로 변환한다.

  * 중복이 있으면 예외.

  * 각 숫자는 1~45 범위여야 한다.

  * 개수가 6개가 아니면 예외.

* 보너스 번호(1개)를 입력받는다.

  * 정수 1개.

  * 1~45 범위인지 검증한다.

  * 기존 당첨 번호 6개와 중복되면 예외.

> 예외 발생 시 IllegalArgumentException 또는 IllegalStateException 등 명확한 런타임 예외를 던지고,
"[ERROR]"로 시작하는 메시지를 출력한 뒤 해당 입력 절차부터 다시 받는다.

### 1-4. 당첨 결과 계산

사용자가 구매한 모든 로또와 당첨 번호를 비교한다.

* 등수 규칙

    * 1등: 번호 6개 일치 → 상금 2,000,000,000원

  * 2등: 번호 5개 + 보너스 번호 일치 → 상금 30,000,000원

  * 3등: 번호 5개 일치 → 상금 1,500,000원

  * 4등: 번호 4개 일치 → 상금 50,000원

  * 5등: 번호 3개 일치 → 상금 5,000원

  * 그 외: 낙첨 (상금 0원)

각 등수별로 몇 개가 당첨되었는지 개수를 집계한다.

### 1-5. 수익률 계산 및 출력

* 총 상금 합계를 계산한다.

* 수익률 = (총 상금 / 구입 금액) × 100

* 소수점 둘째 자리에서 반올림해 출력한다.
  * 예: 총 수익률은 62.5%입니다.

* 당첨 통계 출력 형식
``` JAVA
당첨 통계
---
3개 일치 (5,000원) - 1개
4개 일치 (50,000원) - 0개
5개 일치 (1,500,000원) - 0개
5개 일치, 보너스 볼 일치 (30,000,000원) - 0개
6개 일치 (2,000,000,000원) - 0개
총 수익률은 62.5%입니다.
```

## 2. 예외 및 에러 메시지 규칙

* 모든 잘못된 입력은 IllegalArgumentException 또는 IllegalStateException 등 명확한 표준 예외를 던진다.

* 에러 출력은 항상 "[ERROR] "로 시작해야 한다.
  * 예: [ERROR] 로또 번호는 1부터 45 사이의 숫자여야 합니다.

* 에러 출력 후 해당 입력 단계부터 다시 시도하도록 흐름을 제어한다.
  * (예: 잘못된 구입 금액 → 구입 금액부터 다시 입력, 잘못된 보너스 번호 → 보너스 번호부터 다시 입력)

## 3. 설계 방향 (아키텍처 관점)

> * indent depth 2 이하
> * 메서드 15줄 이하 
> *  else / switch 금지
> *  UI 로직과 도메인 로직 분리
> *  Enum으로 책임 위임

### 3-1. 도메인 / 비즈니스 로직

* Lotto

  * 로또 한 장을 표현한다.

  * numbers: List<Integer> 

  * 생성 시:

      * 숫자 개수 6개인지 검증

    * 중복 없는지 검증

    * 각 숫자가 1~45 범위인지 검증

    * 내부에서 정렬까지 책임질지 여부는 구현 시 결정

* WinningNumbers

  * 당첨 번호 6개 + 보너스 번호 1개를 표현한다.

  * 유효성 검증(범위, 중복 등)을 책임진다.

  * 비교 로직(몇 개 일치하는지, 보너스 포함 여부 등)은 여기서 제공한다.

* Rank (Enum)

    * 1등~5등 + 낙첨(미당첨 포함)

  * 각 등수별:

      * 일치 개수 조건

      * 보너스 포함 여부

    * 상금 금액

  * 정적 팩토리 메서드로 등수 결정:

      * 예: Rank.of(matchCount, bonusMatched)

    * if → return 체인으로 구현하고 else 없이 분기

* Result

    * 여러 장의 로또에 대해 등수별 당첨 횟수 집계

  * 총 상금 계산

  * 수익률 계산

### 3-2. 입력/출력(UI) 레이어

* InputView

  * Console.readLine()으로부터 문자열 입력을 받는다.

  * 구입 금액 입력

  * 당첨 번호 입력

  * 보너스 번호 입력

  * 여기서는 단순히 문자열만 읽어서 도메인 쪽이 처리할 수 있는 형태로 넘긴다.

* OutputView

  * 구매한 로또 수량과 각 로또 번호 출력

  * 당첨 통계 출력

  * 수익률 출력

```[ERROR] ... 메시지 출력```


### 3-3. Controller / Application 흐름

* LottoController (혹은 LottoApplication)

1. 구입 금액 입력 받기

2. 로또들 자동 발행

3. 발행 결과 출력

4. 당첨 번호/보너스 번호 입력 받기

5. 결과 계산

6. 통계/수익률 출력

* 반복 입력(예외 발생 시 재입력)은 Controller에서 담당하며,
도메인 객체들은 예외를 던지는 역할만 한다.

## 4. 테스트 전략

> 조건: “구현한 기능에 대한 단위 테스트를 작성한다. 단, UI(System.out, System.in, Scanner/Console) 로직은 제외한다.”

### 4-1. 테스트 대상

Lotto

* 숫자가 6개가 아니면 예외를 던지는지

* 중복이 있으면 예외를 던지는지

* 범위(1~45)를 벗어나면 예외를 던지는지

WinningNumbers

* 당첨 번호 6개 검증

* 보너스 번호 중복 검증

* 비교 결과에서 일치 개수 계산이 올바른지

* 보너스 번호 일치 여부 계산이 올바른지

Rank (Enum)

* Rank.of(matchCount, bonusMatched)가 올바른 등수를 반환하는지

    * 예: 6개 일치 → FIRST

  * 예: 5개 + 보너스 → SECOND

  * 예: 5개 → THIRD

  * 예: 3개 미만 → MISS (낙첨)

* 각 Rank의 상금(getPrize 등)이 기대값과 동일한지

Result

* 여러 로또에 대해 등수별 개수가 올바르게 집계되는지

* 총 상금 합계가 올바르게 계산되는지

* 수익률 계산이 요구사항대로 반올림되어 나오는지

### 4-2. 사용 라이브러리

* JUnit 5

* AssertJ

    * 예외 검증 예시:
``` JAVA
assertThatThrownBy(() -> new Lotto(List.of(1, 2, 3, 4, 5)))
.isInstanceOf(IllegalArgumentException.class)
.hasMessageContaining("[ERROR]");
```

## 5. 규칙 (코딩 컨벤션 / 제한사항 체크리스트)

들여쓰기(indent) depth는 최대 2까지 허용한다.

메서드는 한 가지 일만 하도록 하고, 15라인을 넘지 않는다.

else 키워드를 사용하지 않는다.

* if (조건) return ...; 형태로 guard clause를 사용한다.

switch / case 사용하지 않는다.

삼항 연산자(?:) 사용하지 않는다.

Rank 등 핵심 분기 로직은 enum을 사용해 표현한다.

camp.nextstep.edu.missionutils.Randoms, Console API를 사용한다.

* ```Randoms.pickUniqueNumbersInRange(1, 45, 6)```

* ```Console.readLine()```

예외는 ```IllegalArgumentException / IllegalStateException``` 등 명확한 타입을 사용한다.

에러 메시지는 항상 ```[ERROR]``` 로 시작한다.

UI 로직(System.out, Console.readLine)은 단위 테스트 대상에서 제외한다.
